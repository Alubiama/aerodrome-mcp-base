## Method receipts

**Creative-lab:** explicit invocation routes the work to the actual blocked function, not cosmetic ideation. Trigger: repeated inability to get the complete basket. Evidence is a real user error screen plus a successful control request. Decision delta: prioritize discovery recovery and actionable feedback instead of another visual redesign.

**Bottleneck locator:** blocked outcome is discovering and previewing useful balances. Candidate constraints: indexer outage (intermittent), RPC page latency (plausible, not measured comprehensively), classic route coverage (observed on one token), wallet execution gate (deliberately protective). Active discovery constraint is PROVISIONAL: a healthy synthetic run disproves permanent total outage but cannot establish the user's failure cause. Metric: one user failure and two successful synthetic server/browser checks, not an uptime percentage. Relief: bounded discovery recovery, explicit failure code, manual fallback. Next test: exercise recovery during a real recurrence and record only its sanitized code; don't erase the sending gate to improve apparent throughput.

**Reinvention prevention:** inspected existing AbortController/sequence handling, boundedJson, local storage, pagination hash, plan guard, native AbortSignal.timeout/any and request admission. Adapt these primitives; no new dependency, router, retry framework, database or wallet stack. Next constraint remains external discovery/route coverage, not lack of another abstraction.

**TRIZ, contradiction separation by condition/time (software analogy):** retrying every provider failure improves apparent resilience but increases delay and aggravates rate limits. Discriminator: HTTP status, native network error and elapsed discovery deadline. One retry only for network/5xx inside the same budget; 429 waits for user recovery and invalid data fails closed. The timeout fallback preserves balance reads. Both transient success and no-retry controls pass. Trade-off remains: a healthy response taking more than five seconds falls back to core tokens; no claim that this timeout is optimal without production observations.

**JTBD:** episode-supported user job: paste an address, see scattered balances, select a basket and know whether collecting is useful before connecting/signing. Screenshot supplies an actual failed episode; it is not evidence of market prevalence. No invented interviews. The established need does not require another discovery interview. Decision delta: preserve the basket on recovery and explain disabled actions. Unknown: how much latency, route coverage and estimated net value users will accept. Next test: one owner-run address → discovery → preview recovery session.
